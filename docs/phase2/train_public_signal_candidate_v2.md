# Train Public Signal Candidate v2

Status: **PROPOSED_NOT_APPROVED_NOT_EXECUTABLE**，2026-11-28。

这是 Train-only 可用性审查后的最小研究修订建议，不是已生效的特征协议。
原 `formal-decision-features-v1`、18 字段基线、模型及所有历史结果保持不变。

## Minimal Candidate

建议另立 `formal-decision-features-v2` 候选：保留原 18 字段及其取值，
仅增加数值二值字段 **`public_completion_unknown`**，共 19 字段。

含义：截至当前决策点，最后一条模型可见工具响应的错误正文是否明确说明
“completion status is unknown”。这表达操作是否完成的公开不确定性，
不能解释为失败标签，也不能据此判断是否需要 Retry/Replan。

| 情况 | 候选值 |
| --- | --- |
| 正常 `Observation` | 0 |
| 可识别的工具错误正文明确包含上述短语，忽略大小写 | 1 |
| 可识别错误正文不含上述短语 | 0 |
| 无法确认响应边界、工具调用对应关系或错误封装格式 | 不发布合格特征；诊断为 UNKNOWN |

只解析最后一条工具响应的错误正文。剥离时须与对应公开工具名及参数完整匹配，
不从参数回显、任务文本、系统示例或框架重试建议中匹配该短语。
异常类型名称仅用于定位正文边界，不作为预测变量。
不读取故障编号、故障分配、注入器状态、环境隐藏 truth、CONTINUE 或 Verifier。
UNKNOWN 不得默认为 0，也不得改记为 Agent 失败。

## Train Evidence and Choice

95 个合格 Train Checkpoint 均保存公开任务、Schema、调用参数和响应，捕获 step=1。
4 条/2 模板命中候选：旧类别 `other` 2 条、`timeout` 2 条。
这说明该位表达与粗错误类别不同的公开维度；不证明它提高预测质量。

审查还发现 `public_unknown_resource` 3 条/2 模板，但在当前 95 行中：

```text
unknown_resource + completion_unknown
    = I(old_error_type == other) + I(old_error_type == timeout)
```

因此在已有错误类别指示列的条件下，两位一起添加至多增加一个线性独立方向。
先只提议完成状态这一位，未知资源保留为诊断摘要；上述等式仅描述本批 Train，
不能当作未来数据的不变量，也不能在未来用故障类型推算字段值。

不建议此时添加的项目：

- 必填参数缺失/多余参数：本批均为 0，不能提供当前训练变化。
- 参数字面标识符与任务不一致：可比较 23 行，其中 4 行不一致；
  一行工具正常返回。精确字面差异不一定违反工具语义，需另审适用规则。
- JSON 返回形状：78 条正常响应可解析，但 Schema 的 output_type 为 any，
  形状本身不足以判定错误，容易充当任务族代理。
- 原始工具名、任务/模板 ID、路径及具体资源 ID：不加入候选字段。

选择依据是公开可计算性、边界清晰和最小增量，不使用本轮 Train 标签关联、
模型指标或 Validation/Test 来筛选。本项目此前已观察旧基线的 Validation，
不能声称整个研究过程从未接触 Validation；本次审查没有再次打开其样本或预测。

## Approval-Conditional Implementation and Acceptance

根据 AGENTS.md 第 4 节，以下是待审核的研究修订，当前不执行：

1. 固定字段定义、匹配规则、UNKNOWN 策略和新版本清单；不改变决策点或标签。
2. 从已校验 Train Checkpoint 生成独立 v2 sidecar；绑定原文件 SHA-256、
   决策步、公开投影 hash、提取器版本及原记录引用，不改旧 CP 或原资格记录。
3. 验收：95/95 可提取、4 个正值、0 个 UNKNOWN，与逐条原始公开错误正文一致；
   原 18 字段完全一致；任务/模板身份只作索引，不进入模型；Train/Val/Test 不混合。
   这些计数针对本批旧 Train 回填，未来批次不要求重复 4/95 的分布。
4. 验证普通 JSON、参数回显/框架建议含同样词语、大小写、错误封装损坏、
   多调用对应关系及未来字段拒绝；未知格式阻止资格发布，保留原始诊断。
5. 若批准比较模型，先另行冻结 Train-only、template-grouped OOF 比较入口，
   使用相同基础模型与参数，保留原基线；不先用 Validation 反复筛选字段或阈值。

当前只完成独立审查函数及审查入口，未把新字段接入生产者、预处理器或模型。
本候选不承诺模型增益；稀疏模板支持仍需后续数据验证。

## When to Collect More Trajectories

**本次审查结束并固定下一批方案后即可准备继续采集，不以模型指标改善作为启动条件。**
如果采用本候选，先完成独立版本及旧 Train 离线回填验收；如果不采用，明确保留 v1。
不需要为补这一位字段重采旧轨迹。

下一批应先扩充 Train：在 Train 模板组内按预先声明的参数生成规则创建新实例，
冻结任务清单、seed、故障覆盖、重复分支、Source Attempt、预算及停止规则。
新 ID 不能代替内容去重；重复同一实例/Checkpoint 的分支不能作为新增独立样本。
需要明确运行/生产版本及 aggregate-family 等历史版本差异如何标记和兼容，
不能无记录混合新旧批次。

当前 Train 95 行、10 个失败。既有 LightGBM 的必要数量门槛是至少 200 行且每类至少 30 行，
即相对当前至少还缺 105 行和 20 个失败；这不是满足功效或泛化的充分条件。
有效特征/样本量门槛尚未注册，LightGBM 仍不能仅凭达到数量就自动启用。
以上是已有门槛的差额，不是“采到第 30 个失败才停止”的新停止规则。
批量大小和批次内停止规则必须提前冻结；不只保留失败，不按已看到的结果临时补采。

建议先冻结一批新的 Train 实例，再按固定批次检查质量、模板/错误信号覆盖和类别数。
这一步与提高模型容量分开处理，也不要求先取得有利的 Validation 结果。
正式批量前按仓库流程重新检查资源及服务，并执行获授权范围内的 Smoke；
本轮没有远端访问或新的采集授权，不启动这些操作。

现有 Validation 已参与诊断，不能将其称为未见过的新验证集。
若需要扩大独立评估，须预先声明新的分组与版本，之后统一评估；
Test 保持封闭，待模型、特征、阈值与评估协议全部冻结后再进入。
